# 老果园更新的跨年收入缺口与苗木订位

`资料/演练.json` 保存本地合成的业务记录，不含个人信息及实际企业数据。各资料集的字段、单位和有效范围见[资料格式](资料格式.md)。需要 Python 3.11，仅使用标准库，从项目根目录运行。

查看资料包的记录数量：

```sh
python3 inspect_packet.py
```

## 业务分析能做什么

这不是“示范园成熟树一年亩产 × 面积”的单点估算，而是一套可以查到每条数据来源、
把同一年景并排比较、并能落地到苗木订位的决策工具：

1. **可查支撑范围的树龄收益**（`renewal/evidence.py`）
   * 每条 `(地区, 砧木, 接穗, 树龄)` 证据保留贡献果园清单、每亩产量/收入/经营支出
     的中位与极差；`min_analogs` 按**不同历史果园个数**计数，不按行数。
   * 只有 `final=true` 的完整年度进证据；在途观察（`final=false`）只列出不统计，
     缺记录的组合返回空证据并标记“待补证”，不补零、不借别处高产园。
   * 旧树锚只取同区、同接穗、树龄相差不超过两年的完整记录。
   * `amendments` 在所有分析之前套用到指定历史字段，并在证据里保留修订标记。
2. **保留旧树 / 立即更新 / 分年更新同情景比较**（`renewal/plans.py`、`renewal/engine.py`）
   * 已清园地块不能退回旧树；清园未种年份只记实际承诺支出；种植当年记树龄零。
   * 情景的价、量系数同时作用于同一年所有地块——多块地的风险按同年景一起吃紧，
     不按互相独立消掉；各情景独立结算，不能跨情景互抵。
   * 逐年模拟现金：已付苗款不扣第二次、未付苗款只在种植年扣一次；年结低于底线可借至
     底线（受 `loan_limit`），有结余先还款；借不满的缺口逐年列出，不用一笔终值掩盖。
3. **苗木订位与联保池约束**（`renewal/allocate.py`）
   * `paid` 订位不可撤销、不可移年；`quote` 是可撤回申请，不预占库存；批次库存和
     起苗期限硬约束，超卖直接拒绝。
   * 联保池按情景、按当年所有户未还占用求和，受 `annual_guarantee_limit` 约束；
     待补证组合不能签需要收益保证的名额。
   * 准备金吃紧时搜索会错开各户更新年份；无法维持保底的家庭单独提示，
     不挤掉不相关组合的已签苗位。
4. **跨轮复议**：新一轮资料重比时，已种地块（`--planted`）与不可撤销订位作为硬约束
   进入；冲突会报错而不是静默替换。
5. **农户可解释输出**（`renewal/explanations.py`）：每户都能看到为什么预计收益更高的
   方案仍不能订，以及哪笔确认支持（现金注入、额外授信、替代批次、待补证据）会改变
   它能选的更新年份。

## 运行

```sh
# 建议用隔离模式，避免工作目录里的同名模块干扰
python3 -I renewal_plan.py evidence    # 输出/树龄证据.json
python3 -I renewal_plan.py compare     # 输出/方案比较.json（三方案×情景逐年现金）
python3 -I renewal_plan.py allocate    # 输出/订位结果.json、输出/农户解释.json
python3 -I renewal_plan.py all         # 以上全部 + 输出/经办摘要.txt

# 新一轮：把已种地块作为硬约束带入
python3 -I renewal_plan.py allocate --planted 已种.json
# 已种.json 示例：{"H2-2": ["R2", 2028]}
```

## 编译与测试

```sh
python3 -m compileall -q renewal renewal_plan.py inspect_packet.py tests
python3 -m unittest discover -s tests -v
```

测试覆盖证据口径与修订、逐年现金/借款/联保、库存超卖、paid 锁定、quote 可撤回、
待补证不得签保证名额、跨轮锁定与冲突报错，以及联保池逐户通过但合计超限必须拒绝。
